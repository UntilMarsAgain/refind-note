# 语法展示

这一页是**样张**，不是手册。每一个模板块、每一条链接，都是程序自己解析出来的 ——
你在这里看到的样子，就是你照抄之后会得到的样子。

读法固定是两步：先看**写法**（代码块里那段），再看它**渲染出来的效果**（代码块下面）。
写法一律包在代码块里 —— 包在里面的 `::` 只是字，不会被当成真的模板块吃掉。
所以这一页能站得住的前提是：**例子本身得跑得通**。

## 一眼看全

模板块的写法只有一种：`::名字 参数=值 …`，然后**缩进**划出块的边界。全内建的有 22 个，
按「块内容被怎么处理」分组：**只写文字的**（`quote` / `aside` / `fields` / `banner` / `title` /
`signature`）、**把一个文件摆出来的**（`image` / `video` / `audio`）、**按 `[标签]` 分节的**
（`tabs` / `theme`）、**把内容原样写出去的**（`code` / `math` / `mermaid` / `html` / `css` / `js`）、
**提示框**（`note` / `tip` / `warning` / `danger` / `error`）。一个模板怎么写，几乎全由它落在哪一组决定。

| 模板 | 干什么 | 参数 |
| --- | --- | --- |
| `::quote` | 带署名的引用 | `origin=` |
| `::aside` | 右侧信息栏，正文绕着它走 | `title=` |
| `::fields` | 左右两栏的属性表 | 无（每行写 `标签 \| 值`） |
| `::banner` | 有底色、占一整行的横条 | `text=` `color=` `height=` `rounded=` |
| `::title` | 居中的大标题，没有底色 | `text=` `color=` |
| `::signature` | 右对齐的落款 | 无 |
| `::code` | 带行号、能标出重点行的代码块 | `lang=` `lines=` `start=` `highlight=` |
| `::math` | 独立成段（或多行）的公式 | 无 |
| `::mermaid` | 图 | 无 |
| `::image` | 图片 | `src=` `alt=` `align=` `width=` `height=` `caption=` |
| `::video` | 视频播放器 | `src=` `align=` `width=` `height=` `caption=` |
| `::audio` | 音频播放器 | `src=` `align=` `width=` `height=` `caption=` |
| `::html` | 原样注入 HTML | `js` `src=` |
| `::css` | 注入样式 | `src=` |
| `::js` | 注入脚本 | `src=` |
| `::tabs` | 选项卡 | 无（块里按 `[标签]` 分节） |
| `::theme` | 同一段内容的深浅两版 | 无（块里按 `[light]` `[dark]` 分节） |
| `::note` | 提示框：说明 | `title=` `color=` |
| `::tip` | 提示框：建议 | `title=` `color=` |
| `::warning` | 提示框：注意 | `title=` `color=` |
| `::danger` | 提示框：危险 | `title=` `color=` |
| `::error` | 提示框：错误 | `title=` `color=` |

除此之外还有三样不是模板块的东西：**内部链接** `[[目标]]`、**页内锚点**（标题自带
`id`，用 `[文字](#标题)` 跳过去）、**公式** `$…$` 与 `$$…$$`。后面各有各的一节。

::note
  **这一页的模板块都是真的**，所以下面的效果不是画出来的图，是渲染出来的 HTML。
  两个例外要提前说清楚：媒体那三个模板引用的文件在帮助目录里不存在，你会看到
  「取不到」的那句说明 —— 那正是文件不在时的样子；而 `::js` 那段脚本会在你打开这一页
  时真的跑一次，所以下面有一行字会被它换掉。

## 块边界由缩进划出

没有开始标记，也没有结束标记。头行之后**缩进更深的行**属于块内，遇到不更深的行就结束：

```text
::note
  这一行缩进了，属于块内。
  这一行也是。
这一行没缩进，块到这里就结束了。
```

::note
  这一行缩进了，属于块内。
  这一行也是。

这一行没缩进，块到这里就结束了 —— 它是一个独立的段落。

为什么用缩进而不用 `::end` 或三反引号：缩进是**已经在用**的那套层级感。模板块套模板块、
列表里嵌模板块，读的人一眼能看出谁是谁；而结束标记要另发明一套配对规则，多一处能写错的地方。
代价是**缩进的四空格代码块被关掉了** —— 两者会互相干扰，一个缩进的模板块很容易先被当成代码块
收走。代码一律用围栏写法（三个反引号）。

还有一条不那么直觉的：**空行不直接结束块**，要往后看一行 —— 后面还有更深的内容，
这个空行才算块内：

```text
::note
  第一段。

  第二段还在块里。

这段已经在块外了。
```

::note
  第一段。

  第二段还在块里。

这段已经在块外了。

参数怎么写：空白分隔，`key=value` 按**第一个** `=` 切；值里有空格就用引号包起来，
引号里可以用 `\"` 和 `\\` 转义。引号没配对，这一行就退回普通段落 —— 宁可当普通文字，
也不猜你想要什么。

```text
::note title="含 空格的标题" origin="他说\"好\""
```

## 只写文字的模板

这一组（`quote` / `aside` / `banner` / `title` / `signature` / `fields`）的共同点是：
**内容照常按 markdown 解析**。所以里面能写链接、列表、内部链接，也能再嵌一个 `::` 块。
参数只管**外框**长什么样。

### `::quote`

```text
::quote origin="某 人"
  内容照常按 markdown 解析：**加粗**、[[Help:首页]] 都算数。
```

::quote origin="某 人"
  内容照常按 markdown 解析：**加粗**、[[Help:首页]] 都算数。

跟 markdown 的 `>` 效果一样，多出来的只是右下角那个署名。不写 `origin=` 就没有署名，
也不会多留一行空白。嵌套时每一层各带一个署名，右下角一层比一层靠里，所以分得出谁是谁的。

### `::aside`

```text
::aside title="十四门桥"
  信息栏里的正文**也**按 markdown 解析。
```

::aside title="十四门桥"
  信息栏里的正文**也**按 markdown 解析。它是一条浮动的栏，正文会绕着它走 ——
  这是信息栏该有的样子。窄屏上样式取消浮动，因为浮动的栏在窄屏上会把正文挤成一条。

### `::fields`

```text
::fields
  地址 | 福建省某村
  分类 | 古建筑
  时代 | 南宋
```

::fields
  地址 | 福建省某村
  分类 | 古建筑
  时代 | 南宋

这一组里 `::fields` 是**唯一**不解 markdown 的：值用的是原文。它是"查参数"用的，
一行一项最清楚，写了 `**` 也不会变粗。没有 `|` 的行把整行当标签、值留空 ——
宁可少一栏，也不丢作者写下的字。

### `::banner`

```text
::banner
  不写参数就是主题色的横条
```

::banner
  不写参数就是主题色的横条

```text
::banner text="福建省文物保护单位" color=#0055a4 height=72px rounded=off
```

::banner text="福建省文物保护单位" color=#0055a4 height=72px rounded=off

关于那几个参数：

- 文案写块里一行、或用 `text=` 给都行，两者都按 markdown 渲染；
- `color=` 给**底色**，只认 `#rgb` / `#rrggbb`；**字色不由你定** ——
  程序按底色亮度算，深底配浅字、浅底配深字。"深底配深字"是最常见的自己给自己挖坑；
- `height=` 给的是**最小**高度：字大了往下长不会被裁掉，给了它就顺带把内容在条里摆正；
- `rounded=off` 要直角，不写就是圆角。

为什么颜色只认十六进制、尺寸只认"数字 + 单位"：这两个值会被写进 `style` 属性。
宽松了就等于允许往里面塞任意声明（`width="1px; background: url(//追踪地址)"`）。
所以规矩是宁可拒掉，也不猜。

### `::title`

```text
::title text="重逢笔记" color=#5b8dd6
```

::title text="重逢笔记" color=#5b8dd6

与 `::banner` 是一对：那条是横条（有底色、占一整行），这个是标题（只有字，居中）。
`color=` 在这里给的是**字色** —— 没有底色可给。

### `::signature`

```text
::signature
  甲  
  2026 年秋
```

::signature
  甲  
  2026 年秋

右对齐的一段，硬换行保留 —— "名字一行、日期一行"照写就是两行。落款里常有内部链接、
强调，所以内容照常按 markdown 解析。

## 提示框：五个，一个形状

`::note` `::tip` `::warning` `::danger` `::error` **形状完全一样**，只有三样东西不同：
记号、配色那一档、默认标题。所以读者是**一眼扫记号**认出这是哪一种提示的，不是读文字认出来的。
底色一律相同，靠左边那条竖条和标题颜色分轻重 —— 五种底色各自调不透明度，迟早互相漂移。

::note
  语气最轻：补充背景、交代一句来龙去脉。

::tip
  值得一试的做法，或者更省事的路子。

::warning
  不做会出麻烦，但眼下还没坏。

::danger
  会丢东西、会不可逆的那类操作。

::error
  已经出错了，或者这样写就是对不上的。

标题可以换，参数只有两个：

```text
::warning title="关于同步"
```

::warning title="关于同步"
  记号还在，只是标题换了。

```text
::note color=#0055a4
```

::note color=#0055a4
  给了 `color=` 就是自定义底色，字色仍由亮度算；左边那条竖条也跟着底色走。

**内容不能空**。空内容的提示框等于什么都没说，所以会直接给一条"用法有问题"的提示，
而不是画一个空框在那里骗人。

## 分节：`::tabs` 与 `::theme`

全库只有这两个按 `[标签]` 分节。分节发生在**扫描时**：每一节各自解析成一篇小文档，
所以一节里能写列表、链接、内部链接，也能再嵌模板 —— 它不是大块里的一段普通文字。

`[标签]` 必须**整行就是一对中括号**并且**与本节其他行左对齐**。第二条是嵌套能分得开的原因：
写得更深就当成里层内容了。正文里一句 `[注] 说明` 不会被误当成新的一节。

### `::tabs`

```text
::tabs
  [北岸]
  北岸的走法……
  [南岸]
  南岸的走法……
```

::tabs
  [北岸]
  北岸的走法：先过桥，再沿河堤走。
  [南岸]
  南岸的走法：
  - 从桥南头下坡
  - 沿老街走到底
  [等一下]
  第一节默认选中，后端只给结构，切换由前端接线。

`[标签]` 的字原样保留（`[API]` 就写成 `[API]`，不会变成小写）。

### `::theme`

```text
::theme
  写在第一个标签之前的内容两边都显示。
  [light]
  浅色主题下看到这一段。
  [dark]
  深色主题下看到这一段。
```

::theme
  写在第一个标签之前的内容两边都显示（`[both]` 是同义写法）。
  [light]
  浅色主题下看到这一段：浅底上的图，用的是浅色描边。
  [dark]
  深色主题下看到这一段。

现在你在浅色主题里，所以只看得见 `[light]` 那一节；切一下主题，另一节就出来了。
**两节都真的渲染进了 HTML**，显示哪一节由样式按当前主题决定 —— 切主题不必重新渲染正文，
就像别的样式一样，当场就变。只认 `[light]` 与 `[dark]`（不分大小写），写别的标签会整块报错，
不会只渲染半截。

## 媒体：把一个文件摆出来

`::image` / `::video` / `::audio` 共用同一套规矩，所以它们住在同一个地方 ——
分开写就会各抄一份，那套规矩迟早走样。

`src=` 必给，写的是**仓库里的名字**，与 `![]()` 里写的是同一个东西。
尺寸 `width=` / `height=` 是**上限**（不是固定宽高，图片不会被拉变形），单位只认
`px` `%` `em` `rem` `vh` `vw`。图注两种写法：在块里写一行（最自然的写法），或者 `caption=`；
`caption=` 优先。

下面三个例子引用的文件在帮助目录里并不存在，所以你会看到「图片不存在」那句说明 ——
那正是取不到时的样子：**留一句人话，而不是一个破图标**，读者不该对着加载失败的方框猜。

```text
::image src=十四门桥.png alt=十四门桥 width=480 align=right
  图注写在块里的一行。
```

::image src=十四门桥.png alt=十四门桥 width=480 align=right
  图注写在块里的一行。

```text
::video src=过桥.mp4 width=640
  一段过桥的录像。
```

::video src=过桥.mp4 width=640
  一段过桥的录像。

```text
::audio src=口述.mp3 caption="作者自己讲的来路"
```

::audio src=口述.mp3 caption="作者自己讲的来路"

`align=` 取 `left` / `center` / `right`，默认居中；只对视频有意义，音频是个窄条。
图片懒加载、长视频只预加载头 —— 一张长文里的十张图不该在打开时就把带宽吃完。

协议只挡能执行或能外传数据的三种（`javascript:` / `data:` / `vbscript:`），其余照常。
另外还有一层与写法无关的照顾：文件进了仓库可能被加密存着，那种情况下直接去拉只会
加载失败，所以取字节之前先问一句"这一份怎么存的、现在读不读得动"，读不动就先摆一个
**解锁框**在那张图的位置上 —— 不是错误状态，所以不用危险色，只是"这一张要先解锁"。

## 原样写出去：代码、公式、图、样式、脚本

这一组的共同点是**正文一概不按 markdown 解析**，但理由分三种，各有各的讲究：
代码、图定义、TeX 里的 `*` `_` `\` `-->` `[]` 都是**另一种语言**的记号，按 markdown 解析就毁了；
`::css` / `::js` 的内容是要**执行**的东西；而 `::html` 是要**落进页面的标记**。

### `::code`

```text
::code lang=rust lines=on highlight=3
  fn main() {
      // 标出来的那一行
      println!("你好");
  }
```

::code lang=rust lines=on highlight=3
  fn main() {
      // 标出来的那一行
      println!("你好");
  }

```text
::code lang=text lines=off
  这一块不显示行号。
```

::code lang=text lines=off
  这一块不显示行号。

- `lang=` 给语言，交给前端的 highlight.js 分词；分词不了也不影响读 —— 原文永远在；
- `lines=off`（也认 `false` / `no`）让这一块**单独**关掉行号，不受全局那个开关影响；
- `start=10` 让行号从 10 起算（写文档时常常要接着上文编号）；
- `highlight=` 写要标出哪几行：`3,5-7` 是逗号分隔的组合，`4-` 是第 4 行到最后。
  它数的是**块里从上往下第几行**，与 `start=` 显示的号不是一回事 —— 两者一起用时
  先看一眼实际效果再定稿。乱写的那几处会**跳过**而不是整条作废：
  一个笔误不该让整块代码失去标记。

::note
  后端只输出代码原文与几个 `data-*` 提示，行号列与强调色带由前端落地。为什么不直接在
  后端生成行号或拆行：拆行会破坏 highlight.js 已经生成的分词（它的 span 可能跨行），
  得不偿失；而"界面怎么显示"本来就属于前端。

### `::math`

```text
::math
  \frac{a}{b} = c_1 * d
```

::math
  \frac{a}{b} = c_1 * d

单行的公式也可以用 `$$…$$`，写在句子里用 `$…$` —— 比如爱因斯坦那句 $E = mc^2$。
`::math` 的好处是**能跨行**，公式长的时候不用想办法折成一行。

正文里看到的是**原文**而不是空白：取不到排版引擎也读得下去，重排时原文还拿得回来。
公式里的 `*` 与 `_` 是数学的一部分，不会被当成强调 —— 这正是它不按 markdown 解析的理由。

### `::mermaid`

```text
::mermaid
  graph TD
    A[写下一个模板块] --> B{渲染出来顺眼吗}
    B -->|顺眼| C[就这么写]
    B -->|不顺眼| D[回去改参数]
```

::mermaid
  graph TD
    A[写下一个模板块] --> B{渲染出来顺眼吗}
    B -->|顺眼| C[就这么写]
    B -->|不顺眼| D[回去改参数]

后端只把原文放进元素里，画图在前端。原文另存一份在 `data-source` 上：画图时配色是定死的，
切主题要拿这份原文重画。画不出来（语法错）就把原文留着、旁边标一下，不在正文里留一个空框。

### `::html`

正文里直接写 `<div>` **什么都不会发生** —— 原样 HTML 是被转义的，因为正文是用 `v-html`
注入的，放行它等于把一个 XSS 入口交给笔记内容。`::html` 是那扇**要自己推开**的门。

```text
::html
  <div class="css-demo">这一段的左边那条竖线来自下面那条 ::css。</div>
```

::html
  <div class="css-demo">这一段的左边那条竖线、那点内边距，都来自下面那条 <code>::css</code>。</div>

默认**净化**：会执行脚本的东西一律不放行 —— `<script>` 整块、`on*=` 事件属性、
`javascript:` 协议都拿掉（它不是完整的净化器，只挡"打开就会跑代码"这条线，够用于
"默认安全、要开 JS 得自己写出来"这个约定）。默认安全，要开就得自己写出来：

```text
::html js
  <script>…</script>
```

### `::css`

```text
::css 颜色=var(--accent-solid) 粗细=4px
  .css-demo {
    margin: 1em 0;
    padding: 10px 14px;
    border-left: {{粗细}} solid {{颜色}};
    border-radius: 8px;
    background: var(--surface);
  }
```

::css 颜色=var(--accent-solid) 粗细=4px
  .css-demo {
    margin: 1em 0;
    padding: 10px 14px;
    border-left: {{粗细}} solid {{颜色}};
    border-radius: 8px;
    background: var(--surface);
  }

上面那一框就是这条样式的产物。四件事值得知道：

- `::html` / `::css` / `::js` 都还认 `src="页面名"`：内容不在块里写，去 `Template:` 命名空间
  里那一页取（名字写页面名，不用带 `.md`）。三样都套用同一套 `{{}}` 填空；
- `{{参数}}` 会被替换成这一块头行的同名参数，`{{body}}` 换成块内容。认不出的名字
  **原样留着** —— 让你看见自己写错了，比悄悄换成空串好；
- 注入的 CSS 与界面在**同一个文档**里，所以本项目所有变量（`--accent`、`--text-dim`、
  `--link-blue`、`--surface`…）用 `var()` 直接就取得到 —— 这正是"自定义样式能跟着主题走"的关键；
- 每条选择器都会被收进**这一页**（加 `.pane__column` 前缀）。不然一条 `* { }` 就能把标签栏、
  菜单、任务栏一起改掉。`@import` 一律丢掉（会让笔记去外部拉样式）。

### `::js`

```text
::js
  for (const slot of document.querySelectorAll(".js-demo")) {
    slot.textContent = "::js 跑起来了 —— 这行字是上面那段脚本换的";
  }
```

::js
  for (const slot of document.querySelectorAll(".js-demo")) {
    slot.textContent = "::js 跑起来了 —— 这行字是上面那段脚本换的";
  }

::html
  <div class="js-demo">（这一行还是占位，等脚本来换。）</div>

脚本在正文注入之后才跑，所以它接得到线。正文是用 `innerHTML` 注入的，那样插进去的
`<script>` 不会执行 —— 前端会把每个脚本**重新装一次**（新建节点、搬过属性与正文），
所以这段代码才真的跑得起来。打开这一页本身就是一次显式的决定：写下 `::js` 就是同意它执行。
内容里的 `</script` 会被转义成 `<\/script`（JS 里这两种写法等价），免得 HTML 解析器提前收尾、
把后面的字漏到页面上。

## 内部链接与页内锚点

`[[目标|显示文字]]`，顺序跟 MediaWiki 一样：**目标在前、显示文字在后**，别写反。
`|` 可以省略，省略时显示文字就是目标本身。

[[Help:首页]]、[[Help:语法展示]]、[[Help:开源协议]] 指向本仓库里真实存在的页；
[[还没写的一页]] 还不存在；[[/子页]] 是"当前页的子页面"；[[zhwiki:条目]] 是**跨站**链接
（默认播种了两个跨站命名空间，删掉就不再生）。

三种颜色各有各的意思，判定是渲染时做的：

| 样子 | 意思 |
| --- | --- |
| 蓝 | 目标在本仓库里存在，点得开 |
| 红 | 目标还不存在 —— 先把这一页建出来，链接就变蓝了 |
| 绿 | 跨站：目标是别人家的页面，点了交给浏览器 |

跨站那两个（`zhwiki`、`qw`）是**播种**上去的：只在新仓库上种一次，之后你删掉它就不会再长回来
—— 默认值不该是"删不掉的东西"。

页内锚点靠标题：每个标题都自带一个 `id`，用普通的 markdown 链接跳过去。
[下面这段是锚点的落点，点它看看](#锚点长什么样)。链接里的 `#` 会被 URL 编码，
前端查之前会先解码，所以中文标题照样跳得动。

### 锚点长什么样

`id` 由标题文字生成：字母数字（含中日韩）原样留下，其余字符归并成一个 `-`，首尾不留 `-`。
所以上面那个落点的 `id` 就是 `锚点长什么样`。

内部链接**故意不带 `href`** —— 带了就会被"凡是 `a[href]` 一律当外链打开"那段逻辑吞掉。
它带的是 `data-doc` / `data-title` / `data-missing`，由前端接管点击。
Ctrl（macOS 是 Cmd）加点击＝在新标签页打开，与浏览器一致。

目标里**不能写 `#段落`**：`#` 在标题里是保留字符（页面名不许带它），所以"跳到某页的某一节"
要在地址栏写 —— 地址的语法是 `命名空间:页面名称[@浏览状态][#段落]`，`@` 与 `#` 的**先后次序自由**
（`名称#段落@状态` 也认得），回显一律按标准顺序排；同名成分后者覆盖前者，空成分算没写。
`@` 后面是状态：`@edit`（去编辑）、`@history`、`@delete`、`@unlock`、`@rollback-版本`、`@view-版本`。
认不出来的状态会报错，不静默裁掉 —— 否则打错的 `@edti` 会悄悄变成阅读页。

## 指令页

正文**第一行**写 `$$COMMAND$$`，第二行写要让程序做的事。这一页就成了指令页：

```text
$$COMMAND$$
REDIRECT: 十四门桥
```

```text
$$COMMAND$$
RANDOM_REDIRECT
```

```text
$$COMMAND$$
RANDOM_REDIRECT: 帮助
```

目前两条：

| 第二行 | 干什么 |
| --- | --- |
| `REDIRECT: <目标>` | 打开这一页就跳到那个地址（目标不能空） |
| `RANDOM_REDIRECT[: 命名空间]` | 每次打开随机跳到某一篇；不带参数就是主命名空间 |

前缀不分大小写；`RANDOM_REDIRECT` 后面要么结束、要么跟冒号 ——
`RANDOM_REDIRECTX` 因此不算这条指令。**认不出来也会报**，而且是最该被找出来的一种：
一打开就把「认不出这一行」和目前支持的清单摆出来，而不是安安静静当普通笔记。

## 用户自定义模板

`Template:` 命名空间（`Template:卡片`）里的那一页，正文就是一个模板。写法：

```text
::卡片 标题="十四门桥" 颜色=#0055a4
  这里写调用时给的内容。

  ## {{标题}}
  正文照常按 markdown 解析，也能再嵌别的模板。
```

那一页里可以写 `{{标题}}` 这样的占位（认不出的名字原样留着），`{{body}}` 是调用时写的块内容。
模板里照样能写 markdown、能嵌别的模板；互相嵌套最多 12 层，超了就停下来并说一声
（多半是自己嵌了自己）。

::note
  `::卡片` 没有对应的 `Template:卡片` 那一页，所以它现在渲染成的是最下面那个
  「未知模板」的框。哪天你建了那一页，这一段就会变成上面那个样子 —— 内置模板的名字
  撞上时按内置的算，不然 `::quote` 会被某个同名页面顶掉。

## 写错了会看到什么

两种错，两种提示，因为作者该往不同方向查：

**名字查不到** —— 渲染成「未知模板」的框，把名字、参数原样列出，内容仍用代码块裹着。
写错了也不该让内容静静消失：

```text
::还没有的模板 标题="含 空格" flag
  内容一行
```

::还没有的模板 标题="含 空格" flag
  内容一行

**名字认识、但用法不对** —— 同一个框加一句为什么。比如颜色不认十六进制：

```text
::banner text="标题" color=red
```

::banner text="标题" color=red
  红色的横条

还有几处是同一个道理：空内容的 `::banner` / `::title` / 提示框、`::mermaid` 与 `::math`
里面没写东西、`::tabs` 有内容写在第一个 `[标签]` 之前、`::theme` 的标签认不出来、
`::image` 缺 `src=` 或用了不许可的协议。全部是**如实说清缺什么**，而不是渲染一个半成品。

## 几条贯穿全篇的规矩

这些不是某一节的话，是整份方言的态度：

- **能解析错就不猜。** 引号没配对退回普通段落，颜色不合法整条拒掉，标题不合法留作字面文本
  —— 猜错比不猜更贵。
- **参数值要往 `style` / `class` 里落，所以只认白名单。** 十六进制、"数字 + 单位"，
  宽松了就等于允许往属性里塞任意声明。
- **默认安全，要开得自己写出来。** 正文里的原样 HTML 转义、`::html` 过滤会执行脚本的东西、
  `@import` 丢掉、`::css` 收进这一页、`javascript:` 协议拒绝、`::js` 要写下 `::js` 才执行。
- **分组是按职责分的，不是按数量分的。** 只写文字的照常解析、把文件摆出来的共用一套校验、
  按 `[标签]` 分节的只有两个、内容原样写出去的不解析、提示框五个共用一个渲染器。
  一个模板的写法几乎全由它落在哪一组决定。
