# 重逢笔记 · refind-note

本地优先的笔记应用：Tauri v2 + Vue 3 + TypeScript。笔记就是你自己磁盘上的一堆文件，
不依赖数据库服务，也不上传任何东西。

## 核心想法：地址栏是唯一权威

界面里所有导航（标签页、正文里的内部链接、页头按钮、前进后退、编辑 / 历史 / 删除 / 回退）
都收敛到**一个** `navigate()`；地址栏显示的内容就是解析结果。地址的形式：

```
命名空间:名称@状态#章节
```

- 命名空间默认是主命名空间（省略不写）；`special:` 是**虚拟**命名空间，不查命名空间表；
- 状态：`view-版本`（默认状态，看的就是最新提交时省略）、`edit`、`history`、`delete`、
  `rollback-版本`；
- 章节：`#小节`，落到正文里对应标题的锚点；
- 顺序可以随便写，回显一律按上面的标准顺序，并且能省则省。

特殊页面：`special:newtab`（新标签页）、`special:settings`（设置）、`special:all`（全部页面）。

## 数据放在哪

全部在 `~/.refind-note/`（仓库根）：

| 路径 | 内容 |
|---|---|
| `notes/0/<id>.log` | 每篇笔记一个**只追加**的 JSONL 事件日志 |
| `blobs/` | 内容块（整份快照与增量的目标） |
| `trash/0/<id>.log` | 删除后的笔记（先写删除标记，再把文件挪过来；历史一条不丢） |
| `titles.json` | `id → 标题` —— **文件名是 id，标题存在这里** |
| `vault.json` | 影响数据语义的设置（首字母是否大写、增量链上限…） |
| `preferences.json` | 界面偏好（主题、主题色、限宽）—— 与笔记一起同步时应当排除 |
| `namespaces.json` | 命名空间表 |

**为什么文件名是 id 而不是标题**：不同操作系统与文件系统对名字的限制、规范化方式都不一样
（大小写、Unicode 规范化、保留字符、长度上限）。id 是纯 ASCII 十六进制，到哪儿都一样；
改名因此只改 `titles.json` 里那一行，不动文件。

## 存储设计

- 事件种类：`meta` / `rev` / `auto`（草稿）/ `del`；`parent` 始终指向前一个**提交**；
- 提交 ID 由事件自身的身份字段做 sha256 得出（**派生，不存储**）；短 ID 取前 8 位十六进制，
  引用时至少写 5 位；全数字的短 ID 先按 ID 前缀试，再退回数字版本号；
- 增量（delta）由四条规则决定"存增量还是整份快照"，并用增量链上限兜底：链太长就让下一版
  退回整份快照，避免读取时一路回放。上限可在设置页调整。

## 编辑器

- 源码用 **CodeMirror 6**，`[[内部链接]]` 有高亮（视图层装饰，不改文档内容）；
- 右侧是**渲染预览**，走与阅读视图**同一个后端渲染器**（`render_markdown` 命令）——
  预览与正文不会出现两套渲染结果；
- 预览不追着输入跑：连续 5 秒没有输入才渲染一次，也可按「刷新预览」立刻渲染。

## 开发

```bash
pnpm install
pnpm tauri dev               # 开发（Linux 需要 WebKitGTK 4.1 与 Rust 工具链）
pnpm build                   # 只构建前端
cd src-tauri && cargo test    # 后端测试
```

## 现状与已知问题

- **已有**：标签页（各自历史、拖放排序、中键关闭）、内部链接（Ctrl/Cmd + 点击开新标签页、
  右键菜单）、版本历史与差异、回退、删除进回收站、主题（深色 / 浅色 / 跟随系统 + 主题色）、
  特殊页面（新标签页 / 设置 / 全部页面）；
- **还没有**：附件、全文搜索（`?query` 已预留）、从回收站恢复的界面；
- 编辑器所在组件的 **scoped CSS 在系统 WebView 下不生效**，因此该组件里的关键布局走
  内联样式与 JS 注入的样式（原因与结论见 `NoteEditor.vue` 的注释）；
- 前端产物超过 500 kB（CodeMirror 占主要部分），尚未做代码分割。

## 关于这个项目是怎么写出来的

**代码由 AI Agent 编写**：人类提出需求、判断取舍、验收结果；Agent 读代码、改代码、跑测试、
提交。这样写出来的代码有两个特点，先说清楚：

- 提交信息与注释会解释**"为什么不是另一种写法"**，包括试过但被否掉的方案 —— 因为很多
  取舍是在调试中定下来的，丢掉理由下次会重犯；
- 出错的方式也和人类不同：会连续几轮在同一个错误假设上打转。所以这里的排查习惯是
  **先造一个能看到事实的通道**（比如一行诊断读数），再下结论，而不是靠推理猜。
